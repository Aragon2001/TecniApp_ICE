## Project Overview

TecniApp ICE is a Kotlin Android application for field operations management at Costa Rica's electricity institute (ICE). It manages electrical meters, outages (averías), luminarias, inventory, vehicles, and project scheduling (planillas/programación). It is a single-module project (`:app`) targeting Android SDK 34 with JDK 17.

## Build & Test Commands

```bash
./gradlew assembleDebug          # Build debug APK
./gradlew assembleRelease        # Build release APK
./gradlew test                   # Run unit tests
./gradlew connectedAndroidTest   # Run instrumented tests
```

Required local setup (not in repo):
- `local.properties` — generated by Android Studio with `sdk.dir`
- `app/google-services.json` — Firebase configuration
- Google Maps API key in `local.properties` as `MAPS_API_KEY`

## Architecture

**Pattern:** MVVM + Repository, offline-first, single-module.

**Data flow:**
```
UI (Fragment/Activity) ↔ ViewModel (StateFlow) ↔ Repository ↔ Room DB
                                                              ↕ (sync)
                                                         Firebase (Realtime DB + Firestore)
```

**Two separate Room databases:**
- `AppDatabase` (schema v27) — main app data; accessed via `RoomRepository` singleton
- `PmDatabase` (schema v1) — Programación/PM module data; separate sync logic

**Sync system:** Background sync via WorkManager workers (`AveriasSyncWorker`, `PmSyncWorker`). The PM module has a `SyncQueueEntity` that tracks pending operations with retry via `RetryPolicy`. Main module sync is handled by `FirebaseSyncManager` and `Synchronizer`.

**Dependency injection:** Manual singleton pattern throughout — `RoomRepository.getInstance(context)`, `AppDatabase.getInstance(context)`, `SessionManager.getInstance(context)`. No Hilt/Dagger.

**Concurrency:** Kotlin coroutines everywhere. ViewModels use `viewModelScope`; the Application class exposes `applicationScope` for app-lifetime operations. StateFlow is used for UI state; Flow from Room for reactive data.

## Key Modules & Entry Points

- `TecniApp.kt` — Application class; initializes Firebase, WorkManager, `applicationScope`
- `SplashActivity.kt` / `LoginActivity.kt` — auth entry points
- `ActivityMain.kt` — main host (navigation drawer + `mobile_navigation.xml`)
- `com.Arasoftsolutions.tecniapp_ice.Database/` — Room entities, DAOs, `AppDatabase`, sync
- `com.Arasoftsolutions.tecniapp_ice.pm/` — self-contained PM module with its own DB, sync, and repository
- `com.Arasoftsolutions.tecniapp_ice.session/SessionManager.kt` — Firebase Auth + SharedPrefs session
- `functions/` — Firebase Cloud Functions (Node.js); deployed separately via Firebase CLI

## Conventions

- **Navigation:** Fragment-based via Jetpack Navigation. Main nav graph: `res/navigation/mobile_navigation.xml`. Planillas has its own: `nav_planillas.xml`.
- **Layouts:** Responsive — `layout/` for default, `layout-sw600dp/` for tablets. Values folders cover night, landscape, and tablet breakpoints.
- **Room migrations:** Defined in `AppDatabase`. Destructive migration allowed from v23 and below; explicit migrations from v24→v25→v26→v27 must be preserved.
- **ViewBinding:** Enabled project-wide. Fragments use the `_binding` nullable field pattern with `onDestroyView` cleanup.
- **Serialization:** Moshi (with KSP codegen) for Retrofit; `kotlinx.serialization` also present for some paths.
- **Document export:** Apache POI for Excel (`.xlsx`), PdfBox-Android for PDF reading.

## Firebase Structure

- **Realtime Database:** Primary sync backend for field data (averías, medidores, etc.)
- **Firestore:** Used in PM module and some newer features
- **Cloud Functions:** `functions/` directory; invoked from the app via `firebase-functions-ktx`. Minimize CF invocations — the app skips CF calls when data is unchanged (see recent commit history).
- **FCM:** `TecniAppMessagingService` handles push notifications; `firebase-messaging-ktx:25.0.1`
